# Agent guide

Working notes for AI agents and new contributors. The README covers what the app is; this covers the things that will bite you.

## What this app is

An internal operator console. It holds admin-only tables in its own database and reads/writes the **live Togetha dev and production databases**. A careless query here touches real customer data. Prefer reading over writing, and never widen data access to make something work.

## Landmines

### 1. Never import an AdonisJS service into client-reachable code

`inertia/` imports helpers from `#utils/*` and `#types/*`. Anything reachable from those imports ends up in the **browser bundle**. Importing `@adonisjs/core/services/logger` (or `app`, or any other service) into such a file resolves the application container at import time and throws in the browser:

```
TypeError: Cannot read properties of undefined (reading 'booted')
```

React never renders and the page is blank — no error boundary, no message. This has already happened once, via `app/utils/functions.ts`.

- Client-safe: `app/utils/functions.ts`, `date.ts`, `currency.ts`, `page_access.ts`, `app/types/*`
- Server-only: `app/utils/run_conditionally.ts`, everything in `app/services/`, `app/models/`, `app/controllers/`

Use `console` or take a logger as a parameter in shared code. To check: `ls node_modules/.vite/deps | grep adonisjs_core_services` should return nothing.

### 2. `adonisrc.ts` is the config; `adonisrc.js` must not exist

A stale compiled `adonisrc.js` once shadowed `adonisrc.ts` for months, silently discarding every config change. It is gitignored. If one reappears, delete it.

### 3. Generated files — do not hand-edit, do not commit churn

- `database/schema.ts` is regenerated by `node ace migration:run` **against whichever database it ran on**. Running the test suite rewrites it against the test DB. Restore it before committing.
- `.adonisjs/**` is codegen from routes.

### 4. Preload environments matter

`#start/boss` is scoped to `environment: ['web']`. Preloaded unconditionally, pg-boss starts polling workers inside every ace command and the test runner, and those processes never exit. If `node ace <anything>` hangs, this is why.

### 5. Middleware order in `start/kernel.ts`

`app_env_middleware` must run **after** `silent_auth_middleware` — it derives the database environment from the authenticated user. Moving it earlier silently falls back to `dev` for everyone.

### 6. Authorization lives on routes, not in controllers

Guards belong on the route group. Do not reintroduce per-method `isAdminOrSuperAdmin` / `getPageAccessForUser` checks in controllers — there used to be 27 of them, they drifted, and several controllers simply forgot. A route outside a gated group is reachable by any signed-in user.

When adding a route under `/api/v1`, confirm `requiredPageKeyForPath` maps it to the right grant, and add a case to `tests/unit/page_access.spec.ts` if it introduces a new path shape.

### 7. Environment resolution is a security boundary

`resolveAppEnv` (`app/services/app_env_service.ts`) is the only thing allowed to decide `dev` vs `prod`. It reads the user, and treats the session value as an untrusted preference. Never add a header, query-param, or body fallback.

## Conventions

- **Imports** use subpath aliases (`#models/*`, `#services/*`, `#utils/*`, `#boss/*`). Frontend uses `@/*` for `inertia/*`.
- **Controllers** stay thin: validate, delegate to a service, transform, respond.
- **Transformers** (`app/transformers/`) shape models for the client — do not serialise models directly.
- **Validation** is VineJS on the server. Use `vine.enum` for anything that maps to a fixed set (a DB connection name, a status) — `vine.string()` lets bad values reach the query layer.
- **Errors** go through `logger`, not `console`. Never return driver details (table, column, constraint) to a client.
- **Formatting** is oxfmt (`npm run fmt`), not Biome. Format only files you touched; a repo-wide reformat buries the diff.

## Before you say it works

```bash
npm run typecheck
npm test
```

Both must pass. For anything touching `inertia/`, middleware, or shared utils, that is **not sufficient** — the server can return a perfect response while the page renders blank. Load the app and confirm the screen actually renders:

```bash
rm -rf node_modules/.vite && npm run dev
```

Clearing the Vite cache matters: it caches pre-bundled dependencies and will keep serving a broken module after you have fixed the source.

## Gotchas that are not bugs

- `__transmit/events` connection failures in dev — the Transmit client points at a fixed port that may not match `ace serve`'s.
- React hydration mismatch warnings — `inertia/app.tsx` calls `hydrateRoot()` while `config/inertia.ts` has `ssr.enabled: false`. React recovers by client-rendering. `createRoot` would be correct; changing it is a standalone fix.
- 500s from `/api/v1/dashboard/*` on a machine that cannot reach `DEV_DB`.
